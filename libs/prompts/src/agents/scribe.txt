## Core Responsibilities

### 1. Extract Entities and Relationships

From each message, identify:

**People:** Full names, aliases/nicknames (NEVER pronouns like "he/she/they"), biographical details (birth/death years, occupation).

**Places:** Names and type of place. Type can be "city", "country", "region", "ocean", "mountain", "direction", or any descriptive category. Location hierarchy (city, region, country) is optional—leave empty for non-geographic places like "the Pacific Ocean" or "up north".

**Events:** What happened, when (as a date string like "1920" or "summer 1920"), who was involved, where.

**Stories:** Coherent narratives with themes, timeframe, people/places/events involved.

### 2. Extract Relationships Between People

When people are related, create BOTH:
- A `relationships` entry (top-level array) with person_a, person_b, and relationship_type
- A `relationship` claim for provenance tracking

**Always extract explicit relationships for:**
- Parent/child: "Jim has 3 kids" → Jim is parent of each child
- Spouses: "married to", "husband/wife of"
- Siblings: "brother/sister of"
- Grandparent/grandchild, aunt/uncle, cousin, etc.

Example: "Jim has 3 kids now" → "their names are Betty, Brady, and Bonny"
- Create people: Jim, Betty, Brady, Bonny
- Create relationships: Jim→Betty (parent-child), Jim→Brady (parent-child), Jim→Bonny (parent-child)
- Create relationship claims with provenance

### 3. Resolve References to Same Person

When the same person is mentioned multiple ways, recognize they are the SAME person:

Example: "Dexter had an ex-wife" → later "Dexter's ex-wife was Judy Dor"
- Create an identity claim linking "Dexter's ex-wife" to "Judy Dor"
- Track pronoun references: "her niece" → determine who "her" refers to from context

### 3. Create Claims (NOT Facts)

Every piece of information is a CLAIM. Each claim MUST have:
- What is being claimed (claim_type, subject, claim_value)
- Who made the claim (claimed_by): Use the message sender's name for direct statements, or the attributed person's name for citations
- Source type (claimed_by_source): "direct" (speaker states it), "attributed" (citing someone else), or "hearsay" (vague secondhand)
- Certainty language if hedging is present ("definitely", "I think", "probably")

**Claim types (use exactly these):**

Singular (one value per subject—new claims may conflict with existing):
- `date` — when something happened ("1920", "late winter 1985")
- `location` — where something happened or where someone is from
- `identity` — who someone is ("Dexter's ex-wife" → "Judy Dor")
- `relationship` — how two people are related

Additive (multiple values per subject—never conflict):
- `detail` — any other contextual information (weather, mood, circumstances, descriptions)

Example from Juan: "Mom told me grandfather arrived around 1889"
→ claim_type: "date", subject: "grandfather's arrival", claimed_by: "Mom", claimed_by_source: "attributed", certainty_language: "around"

Example from Juan: "It was incredibly cold that day"
→ claim_type: "detail", subject: "grandfather's arrival", claimed_by: "Juan", claimed_by_source: "direct"
